**Findings**
- High: Off-host backup is allowed to silently fail. [lib.sh](C:/Users/USER/Documents/autoworkshop-ai/infrastructure/backup/lib.sh:135) returns success when MinIO is unavailable, so [backup.sh](C:/Users/USER/Documents/autoworkshop-ai/infrastructure/backup/backup.sh:181) still completes, prints a backup stamp, and then runs retention pruning. For a normal backup run, this should be fatal unless `--no-offhost` was explicitly requested.

- High: The “separate credentials” guarantee is not implemented. [lib.sh](C:/Users/USER/Documents/autoworkshop-ai/infrastructure/backup/lib.sh:128) uses `S3_ACCESS_KEY` / `S3_SECRET_KEY`, which are also the MinIO root/application credentials in [docker-compose.yml](C:/Users/USER/Documents/autoworkshop-ai/infrastructure/docker/docker-compose.yml:124) and `.env.example`. That contradicts the security claim in [backup.sh](C:/Users/USER/Documents/autoworkshop-ai/infrastructure/backup/backup.sh:176) and [BACKUP_AND_RESTORE.md](C:/Users/USER/Documents/autoworkshop-ai/docs/05-database/BACKUP_AND_RESTORE.md:71). Use distinct `BACKUP_S3_*` credentials with a policy limited to the backup bucket.

- Medium: `backup.sh` claims every run is gated by real archiving verification, but it only checks historical `pg_stat_archiver` state. [archiver_healthy](C:/Users/USER/Documents/autoworkshop-ai/infrastructure/backup/lib.sh:99) can pass after an old successful archive even if the archive path or command is currently broken and no newer attempt has happened. The backup gate should force a WAL switch and observe `archived_count` advance, like [verify-archiving.sh](C:/Users/USER/Documents/autoworkshop-ai/infrastructure/backup/verify-archiving.sh:37).

- Low: The manifest writes missing realm as the string `"null"`, not JSON null, at [backup.sh](C:/Users/USER/Documents/autoworkshop-ai/infrastructure/backup/backup.sh:166). Labels and other interpolated values are also not JSON-escaped. Use `jq -n` or another JSON writer for the manifest.
