### 🔴 AND MY FIX FOR ONE OF THOSE SEVERED THE DOCKER STACK. Recorded in full.

Widening the kill list to include `start-local.sh`'s ports, I matched any
`<word>:<port>`:

```python
re.findall(r'\b[a-z][a-z0-9-]*:(\d{4,5})\b', launcher)   # WRONG
```

That also matches **`localhost:8080` inside a URL**, so **8080 entered the kill
list**. Section 2 killed the process listening on 8080 — on Windows that is
**Docker Desktop's port proxy, not an app**. It took the Docker API pipe with
it: `docker ps` failed outright, and postgres/minio/keycloak all probed as down.
**A self-inflicted outage that reads exactly like the 2026-08-01 host-forwarding
fault this script exists to detect.** Docker Desktop had to be restarted by hand.

**Two independent guards now, because either alone would have stopped it:**
1. **Anchor on `APPS`** — only pairs on a line mentioning `APPS` are app ports.
   A port inside a URL is not an app port.
2. **`INFRA_PORTS` may never be killed**, whatever any parse says —
   `5432, 8080, 6379, 4222, 9000, 9001, 3478, 1025, 8025`. They belong to the
   containers section 3 checks. The refusal is **printed**, not silent.

Proven in isolation before re-running anything that kills:
```
3000,3001,3002,3006,4000,6006,8081     ← kill list; 8080 GONE
GUARDED 8080                            ← refused, and it says so
LAUNCHER 3001,3002,3006                 ← the launcher's real app ports
```

⚠️ **The lesson worth keeping: a widened kill list is a DESTRUCTIVE change and
must be dry-run before it is executed.** I ran it live. The port-scan block can
be executed standalone — do that first, every time.

The script now ends with **`passed / failed / SKIPPED / warnings`** as four
numbers plus a non-zero exit on failure, because *a skip is not a pass* and it
previously had no way to say either.
